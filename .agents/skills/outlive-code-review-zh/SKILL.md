# 代码评审

只读评审；不代替用户合并或修改 PR。遵循[仓库规则](../../../AGENTS.md)，英文等价入口见 [outlive-code-review-en](../outlive-code-review-en/SKILL.md)。

1. 确认待评审的准确 base/head 和工作树状态；读取完整差异、关键调用方、[当前模块文档](../../../docs/modules/)和相关 [Agent Notes](../../notes/README.md)。V2 目标文档不能当作现有实现证据。
2. 对每个实际触及的边界追踪：事件与持久化谁是真源；模型可见事实是否已有证据；工具动作是否具备 Command、Receipt、Observation 和 unknown/reconcile；审批、凭据、沙箱和 workspace 权限是否可从另一入口绕过；取消、重试、恢复是否有界；协议/存储升级是否兼容。
3. 检查测试是否从外部可观察结果证明回归，尤其是失败、崩溃、并发、取消和反向用例。新增接口要看真实消费者和清理路径。对照[推送前验证](../outlive-pre-push-zh/SKILL.md)核对已运行证据，但“绿灯”不等于语义正确。
4. 只报告可定位的问题：文件与行、触发条件、影响、依据、优先级。区分阻塞问题、建议和待确认问题。若没有发现问题，也列出评审范围与未验证风险；不要虚构缺陷。

评审本身不执行写操作。必要的只读/可逆诊断可做；不要为“证明”问题去更改用户文件、外部服务或发布状态。
