# GOAL-099：持久批准与共享请求准入

## Context

此切片遵循[产品工作台计划](../proposed/2026-10-05-complete-product-workbench.zh.md)。Goal 必须包含用户可观察的完成条件，以及至少一项有限时间或 token 上限。Run 完成只提供审阅证据，不等于 Goal 最终验收。既有子 Agent 预算不能覆盖父请求、供应商重试、修复、摘要与子 Agent 的累计上限。

## Decision

使用既有 SessionEvent Ledger 流记录有版本的 Goal 提案、命令、Run 引用及共享预算检查点。批准绑定精确 Goal 版本；启动和继续是另外的人为命令。恢复不得自动重发模型请求或未知写入。只有用户显式最终验收才能把 Goal 标为完成。

在 Run 准入传入可信 Core 请求预算接缝，子 Run 继承同一对象。每次真实供应商 HTTP 发出前，预留保守文本输入上限与强制输出上限，持久记录预留，并施加剩余时间期限。已验证用量可释放未用额度；用量缺失或未知则消耗全部预留，暂停后续派发等待审阅。时间与 token 独立限制。缺少该边界的适配器拒绝预算任务。定时器限制派发并中止活跃工作，不只是稍后刷新 UI 数字。Goal Run 禁用可选后台模型衍生，避免未记录费用。

## Scope and compatibility

Goal 输入不包含凭据、任意 Runtime 策略或未验证工作区路径。Host 准入复用 ConversationControl、已登记项目、权限快照、工作区协调器与不可变模型租约。暂停需收敛活跃 Run；进程恢复只能人为继续，并继承剩余预算。首切片启动一次已批准执行 Run，保留真实结果供最终验收；独立调度/循环引擎与真实付费供应商质量仍属后续工作。可靠价格缺失时不声称金额上限可执行。

首个接受的 Run 将 canonical Session 绑定到 Goal 快照。人为继续复用该会话，仅携带本 Goal 已链接且 scope 验证一致的有界公开任务/结果；私有推理、Tool/Artifact 原文和临时答案不进入历史。接受 Run 后绑定回执丢失时保持未知。精确命令与创建核对均只读、不派发；失败或未知创建不能声称已获得 Goal 定位。预算 Goal 排除未校准图像输入和外部图像生成，不虚构其费用。

## Validation

验收精确批准版本、命令幂等/冲突、未批准不创建 Run、有限预算、请求前拒绝且供应商调用为零、并发子预算、真实协议修复/重试与超时、用量缺失/未知、重启额度保留、暂停继续、Run 失败与用户最终验收。不用合成计数或 HTTP 200 证明 Goal 成功。

已验证切片通过最终 Core 定向检查（9 文件、108 测试）、Host 续接检查（16 测试）、契约（2 文件、8 测试）及 Core/Host 类型检查。真实本地 HTTP 覆盖父子请求、供应商输出额度、修复、摘要、期限、未知用量和同 Session 公开历史续接；实际未知磁盘效果仍被阻止重试。见[范围明确的证据](../../../docs/validation/goal-099/README.zh.md)。本 Note 只把已验证源码/控制器切片标为 implemented；作为完整产品任务的 GOAL-099 与 FLOW-097 仍部分完成，等待客户端、自主推进和最终验收。
