# Production budget compatibility: test fixtures and recovery

[中文](host-fixture-compatibility.zh.md)

This supplement preserves production `deliveryReview` admission. Legacy in-process test adapters now use a [test-only reservation adapter](../../../packages/host/test-support/budgeted-fixture-model.ts). It reserves before invoking their decision producer, bounds serialized output to the actual reservation, settles explicit synthetic fixture usage and retains a conservative unknown charge if the result is lost. These serialization units are protocol fixtures, not paid-provider tokens or quality evidence. A real `ConfigurableModelAdapter` is not wrapped or double-charged.

The [final serial receipt](checks/host-budget-fixtures-final2.log) passed five files / 26 tests: `project-file-context`, `readonly-preview`, `subagent-worktree-runtime`, `composition/recovery-policy` and the new reservation-adapter negatives. Production sources, finite defaults and unknown handling were not relaxed. Underflow invokes zero decision producers; known synthetic results produce real reserve/settle facts; lost results conserve the held charge.

The read-only preview oracle still verifies an actual approved `patch.applied`, changed source bytes, the same live HTTP service PID and release of the Run's writer lease. Its fake writer supplies no verification command, so its correct new terminal is `failed / delivery_verification_missing`; this is not a successful software delivery. The earlier [preview proof](../dev-readonly-preview/README.md) remains historical evidence of the file/process boundary.

Recovered authority remains covered with a real explicit execution Plan: create Todo, submit plan, restore without dispatch, resume the same pending plan, then change project rules and reject the exact plan approval with `resume_policy_changed`. The old test's unsupported adapter and implicit successful software resume do not bypass the new policy. The earlier receipt predates ordinary finite-delivery continuation. Its legacy adapter lacks an immutable recovery identity; that negative now requires `delivery_model_binding_missing`, retains original reservations/source bytes and dispatches nothing. Actual same-budget software continuation is separately verified in the [human-continuation slice](../delivery-human-continuation/README.md); this historical fixture receipt does not establish that newer feature.

The [initial serial receipt](checks/host-budget-fixtures-final.log) retains one fixture-only route error (`/approve-plan` returned 404). The actual route is `/plan/approve`; the second receipt is the verified result. The root's wider parallel-suite failures remain in its original logs. These focused results do not replace final full-workspace or native-install verification.
