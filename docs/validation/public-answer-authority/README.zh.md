# 回答权威验证

[English](README.md)

本次源码级 Workbench 修复让持久任务结果优先于易失模型回答候选。不修改 Runtime、SDK 传输、事件格式或存储历史；验证没有发出模型请求、原生输入，也未使用用户默认配置。重建后的安装包图形验收另行记录。

## 已验证行为

完成、历史与待审阅视图只显示持久结果，即使保留的回答快照与之冲突。失败、取消、中断和人工审查状态显示持久错误，不显示先前成功口号。已挂载的渐进草稿在状态切换时立即被替换，不会继续播放旧候选并伪装成最终答案。

完成、历史或待审阅投影没有 outcome 时，界面仅提示暂无最终回答并引导查看已记录活动。没有验证事实的规范完成事件不能凭空证明生成物或验证结果；易失的成功候选也不得替代缺失回答。

运行期间，仅当前模型调用的明确公开回答可作为**回答草稿 · 尚未核验**显示，没有正式复制或赞踩控件。对应规范决定、无效输出/失败/取消事实，或更新的规范模型请求，使候选失效。因此第一次 finish 候选在只读交付审阅、修复和验证继续时消失；新的当前调用仍可显示公开草稿。表面流 cursor 与账本 sequence 使用不同序列，测试故意把旧 cursor 设得远大于新事件序号。

完全没有模型操作历史的旧服务保留带标签的公开流式兼容；已有历史时，无法绑定调用的候选不能借用另一调用的权威。失败/取消快照与私有思考不显示。这项保守显示规则不声称任何运行草稿已通过验证。

## 证据

- [修复前](checks/before-fix.log)：15 项新增反例在旧组件下全部失败；终态显示冲突的成功候选，交付审阅及失败候选仍可见，草稿没有标签。
- [最终定向测试](checks/targeted-final.log)：3 个文件、29 项通过，包含新增 15 项权威反例、既有公开进度与 UX 旅程测试。
- [Workbench 类型](checks/types-final.log)：退出码 0。
- [语言测试](checks/locale-final.log)：1 个文件、11 项通过，中文明确标示尚未核验。
- [翻译登记检查](checks/i18n-final.log)：89 对已登记、0 对未登记；仅父任务维护的 flow-team-delivery-review Note 并行修改导致 hash/结构漂移失败。本切片两对文档已机械登记，不声明人工翻译审核；父任务在该 Note 冻结后刷新指纹。

真实挂载 React 测试覆盖草稿 → 交付审阅继续 → 持久失败 → 不同的持久完成答案，期间不重新挂载；草稿与失败不读取赞踩，规范完成后仅读取一次。SSR 分别核对终态优先级、兼容公开文字、模型身份、审批状态与私有推理过滤。这些是受控组件夹具，不代表付费模型质量或已安装原生图形行为。

上述原始证据之后，独立 UI 审查发现回答缺失的兜底文案问题。[补充修复前](checks/missing-outcome-before-fix.log)，完成、历史、待审阅三项新增反例均因“已验证结果”的无证据声明失败。[补充修复后](checks/missing-outcome-after-fix.log)，两个定向文件、28 项通过；每项新增反例均核对中英文、形状符合规范的完成事件及没有生成物/验证证据的条件。[Workbench 类型](checks/missing-outcome-types.log) 退出码 0。本次补充没有模型请求、构建、已安装应用启动或原生输入。
